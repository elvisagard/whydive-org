# WhyDive.org Strategic Reference

## Purpose

WhyDive.org is the public home of the WhyDive framework.

It exists to explore, develop, and communicate the relationship between evidence, reasoning, judgment, decision-making, and human flourishing. It should not be treated primarily as a product site, sales site, district implementation site, or K-12 education site.

This strategic reference should be read alongside [WhyDive Foundational Thesis](./whydive-foundational-thesis.md), which defines the human problem, the WhyDive observation, the core thesis, and the long-term vision for the framework.

It should also be read alongside [WhyDive Whitepaper Roadmap](./whydive-whitepaper-roadmap.md), which defines the publication hierarchy for framework, architecture, application, and future-domain documents.

The core invitation is:

> Dive into the why behind what you believe, conclude, and decide.

## Governing Principle

Strong conclusions require strong evidence.

Every page, essay, whitepaper, and application overview should help cultivate disciplined judgment: helping people align conclusions with evidence, recognize boundaries, resist overclaiming, and move from evidence toward wise action.

The central framework question is:

> What conclusions are justified by the evidence available?

## Legal and Contact Posture

For now, WhyDive should use the same public contact information as Living Spiral Studio LLC.

WhyDive is currently owned and operated under Living Spiral Studio LLC. Future work may make WhyDive a separate legal entity, but current public language should not imply that separation has already happened.

Footer, contact, privacy, terms, and support language should therefore reference Living Spiral Studio LLC where legal or operational identity is required.

## Implementation Implication

The first version of WhyDive.org can be frontend-first. The current backend is starter infrastructure only, so backend deployment is not required unless the site adds contact forms, newsletter capture, account features, CMS-backed publishing, search, or other server-side workflows.

The site should be designed as an authoritative framework and publishing home first, with careful outbound paths to the existing application sites.
